# Phase 1 — Explore

유사 도구·제품·기법 리서치. 선택지 3개 이상 비교.

## 입력

`tasks/{task_id}/phase0/request.json`

## 출력

`tasks/{task_id}/phase1/exploration.md`

```markdown
# Exploration — {topic}

## 비교 후보

| # | 이름 | 유형 | 라이선스·가격 | 태블릿 친화 | Aura 적합성 |
|---|---|---|---|---|---|
| 1 | Kleki | 웹 페인트, MIT | 무료 | ★★ | ★ |
| 2 | Drawpile | 웹 페인트+협업, GPL-3.0 | 무료 | ★★★ | ★★★ |
| 3 | miniPaint | 웹 이미지 에디터, MIT | 무료 | ★★ | ★★ |

## 각 후보 장단점

### 1. Kleki
- 장점: …
- 단점: …
- Aura 적합 지점: …

### 2. Drawpile
...

## 핵심 비교 축

- 기능 풍부도 (브러시·레이어·블렌드)
- 라이선스·격리 부담
- 태블릿(갤럭시 탭 S6 Lite) 실측 성능
- 인프라 비용

## 결론(1차 권고)

에이전트가 제안하는 1순위와 근거 한 문단.

## 참조 링크

- [공식 문서](...)
- [벤치마크 글](...)
```

## 절차

1. `WebSearch`로 주제 관련 대안 도구·사례 3개 이상 수집
2. 각 후보의 라이선스·가격·임베드 가능 여부·태블릿 성능·커뮤니티 상태 확인
3. `WebFetch`로 공식 문서 1개 이상 확인 (버전·API 시그니처 등 정확도 요하는 정보)
4. 비교 테이블로 정리, 각 후보에 한 문단 장단점
5. 에이전트 1순위 권고 + 근거

## 자율 진행 지침

- 리서치 결과만 정리. 최종 선택은 phase3(interview)에서 결정.
- 사용자 이전 대화에서 이미 후보 힌트 줬으면 그걸 포함하되, **검증은 최신 리서치로**.
- 라이선스는 반드시 명시 (MIT/GPL/BSD 등).

## 검증 게이트 (탐색 검증)

- 비교 후보 ≥ 3개
- 각 후보에 장단점 ≥ 2개씩
- 라이선스·가격 필드 비어있지 않음
- 참조 링크 ≥ 2개

미달 시 phase1 재실행.

## 스킵

`scope == "parking"`이면 phase1 실행 안 함. `scope == "research_only"`면 phase1이 최종 산출물이고 이후 phase 전부 스킵, 결과를 `research/`에 복사.

## 핸드오프

`exploration.md` 한 파일 phase2에 전달.
